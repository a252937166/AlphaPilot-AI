## 2. Exact conflict and why the old two-file authority is insufficient

The conflict has three layers.

First, r1 section 4.3 explicitly retained the specialized epoch-8 landing
validator unchanged. Its landing-document binding expects implementation epoch
`8`, and the registered preflight dispatch enters that complete path only when
the requested implementation epoch equals `8`.

Second, r1 sections 6.2 and 7 require the locked exact-OS positive and the real
registered-root preflight to run with implementation epoch `9`, the epoch-9
implementation commit, the epoch-9 owner authority, the epoch-9 independent
review, and the epoch-9 landing report. A landing report that truthfully records
epoch `9` cannot pass an unchanged epoch-8 document validator. A landing report
that falsely records epoch `8` would violate the latest-landed and current-byte
invariants.

Third, the same epoch-8 live value is independently enforced after preflight:

1. the producer validates the Q embedded preflight, landed execution epoch,
   R execution envelope, B topology, recovery start, claim, mirror receipt,
   recovered-publication capability, and recovered-release result against the
   epoch-8 live anchor;
2. the validator independently validates the epoch-8 companion contract,
   Q/R/B, preflight, live execution anchor, passive recovered bundle, passive
   recovered release, and release receipt against the same live value;
3. both modules correctly keep the historical selected attempt at epoch `6`,
   but currently have no separate registered representation for a latest live
   epoch of `9`.

Fourth, the producer's `validate_epoch_8_recovery_contract` still passes all
five immutable epoch-8 governance source references through the generic
first-parent-only `validate_unique_a_authority`. At the current registered
lineage those five source documents also have lawful first-parent merge
projections through `d9838923...`. The generic helper sees the projection while
the historical contract correctly names each logical source. Once the first
owner-authority refusal is repaired, this would deterministically become the
next refusal. The five paths are the epoch-8 design proposal, design review,
governing adjudication, companion, and surface authority. This is the same
source/projection identity class, not permission to change their bytes or
topology.

Therefore a producer-only implementation could make the initial source
projection test pass while leaving a deterministic validator or downstream
recovery/release refusal. That would recreate the prior “one wall later” class.

The authority at commit `6936f453...` is valid evidence of the scope that was
approved, but its two-file content is now proven insufficient. It cannot be
used to modify the validator or validator tests, and it cannot truthfully
deliver the required end-to-end epoch-9 path without those changes. It must
remain immutable in history and must not be amended or silently broadened.
Before implementation resumes, a new adjudication must classify this conflict,
a new companion must encode the corrected contract, and a new six-field
surface authority must explicitly supersede the old authority and approve the
four-file surface. Epoch remains `9`; no implementation candidate was
authorized merely by discovering this design defect.
