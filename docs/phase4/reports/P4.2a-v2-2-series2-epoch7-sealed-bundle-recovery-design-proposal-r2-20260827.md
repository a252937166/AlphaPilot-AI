## 5. Capability-gated mode separation

### 5.1 Exact internal modes

The implementation uses a closed internal enum, not booleans or optional defaults:

```text
ACTIVE_ATTEMPT_BUNDLE
PASSIVE_RECOVERED_BUNDLE
PASSIVE_RECOVERED_RELEASE
```

- `ACTIVE_ATTEMPT_BUNDLE` preserves the ordinary attempt-built validator and active replay path.
- `PASSIVE_RECOVERED_BUNDLE` is the r1 recovery-time staged bundle validation.
- `PASSIVE_RECOVERED_RELEASE` is the new post-publication release revalidation path.

No mode may fall back to another. An unknown mode is an error. Static call-graph tests prove the recovered modes cannot reach active replay symbols.

## 7. Recovered-release validation algorithm

The read-only consume entry runs in this order:

1. Validate locked process, launcher, orig-argv executable, environment, direct entry and argument mutual exclusion.
2. Validate R and B canonical bytes, Git topology, owner text and exact mutual binding without reading external recovery storage.
3. Read the fixed `RELEASE_RELATIVE`; validate its canonical bytes, unchanged release schema, unique-A creation, authority references, reviewed head and execution-head ancestry.
4. Validate the epoch-7 `LiveExecutionAnchor`: owner authority, implementation, review, landing projection/report, all current control members, loaded producer/validator identities and current real-lineage census.
5. Only now inspect registered recovery storage. Derive and validate the exact `RecoveredPublicationCapability`; require one success claim and no conflicting or partial recovery state.
6. Read the fixed official bundle and run the complete common bundle pass in `PASSIVE_RECOVERED_RELEASE` with `HistoricalSelectedAnchor(epoch6)` and `LiveExecutionAnchor(epoch7)`.
7. Revalidate the sealed series history, selected started/candidate/terminal bytes, `[5,6]` epoch table, control/harness/module archives, Merkle roots, bundle filesystem, second-copy history and the exact historical full-downstream-replay evidence in section 8.1.
8. Cross-validate every release/bundle equality and require the release reviewed-head Git blob to equal the published destination bytes and capability digest.
9. Revalidate destination versus secondary snapshot and both recovery receipts.
10. Re-run the live anchor and real-lineage census; require all read-only before/after fingerprints equal.
11. Return one canonical JSON result with `status=PASS_READ_ONLY_RECOVERED_RELEASE_REVALIDATION`, zero effects and the bound release/bundle/recovery/census digests.

The successful result is validation evidence only. It preserves the existing release receipt's locks and does not declare P4.2a done or unlock P4.2b, P4.3, held-out evaluation or trading.

The recovered path never calls:

- `_active_replay_validated_bundle`;
- `_active_replay_selected_pipeline`;
- `_official_validator_replay_scope`;
- `replay_selected_pipeline`;
- `_execute_pipeline_inner`;
- attempt allocation or ledger writers;
- model, network, database, held-out or trading code.

## 8. Coverage-preservation argument for release

The release correction preserves both times instead of collapsing them:

```text
release bundle selected identity
    == sealed ordinal-2 bytes
    == immutable epoch-6 Git/archive bytes

release validator executing identity
    == latest landed/reviewed epoch-7 Git bytes
    == current worktree and loaded modules
```

The release receipt still binds the exact reviewed repository head and exact bundle Git blob. The recovered-publication capability adds proof that those bundle bytes are the same bytes published by the one authorized recovery and mirrored with paired receipts. Passive mode removes only regeneration; it does not remove any schema, lineage, Git, archive, Merkle, filesystem, mirror, receipt, current-code or reviewed-head check.

Historical tampering fails the epoch-6 anchor. Current-code tampering fails the epoch-7 anchor. Recovery-provenance tampering fails capability construction. Release-document tampering fails the unchanged release controls. Bundle mutation fails destination, snapshot, receipt, reviewed-head Git blob and release-reference equalities.

There is no weaker fallback. A recovered bundle without the exact capability is rejected, not actively replayed.
