```python
class BrokerOrder(Base):
    __tablename__ = "broker_orders"
    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    proposal_id: Mapped[str] = mapped_column(String(64), index=True)     # 关联 trade_proposals.proposal_id
    futu_order_id: Mapped[str | None] = mapped_column(String(64), unique=True)
    symbol: Mapped[str] = mapped_column(String(24))
    side: Mapped[str] = mapped_column(String(8))
    order_type: Mapped[str] = mapped_column(String(16), default="MARKET")  # v1 只用限价单模拟市价：last*1.01/0.99
    price: Mapped[float | None] = mapped_column(Float)
    qty: Mapped[float] = mapped_column(Float)
    status: Mapped[str] = mapped_column(String(24), default="submitting")
    # submitting/submitted/filled/partial/cancelled/failed
    filled_qty: Mapped[float] = mapped_column(Float, default=0)
    avg_fill_price: Mapped[float | None] = mapped_column(Float)
    environment: Mapped[str] = mapped_column(String(12), default="SIMULATE")  # 永远 SIMULATE，见守则
    error: Mapped[str | None] = mapped_column(Text)
    created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), default=utcnow)
    updated_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), default=utcnow, onupdate=utcnow)
```

trade_proposals 状态机扩展（迁移无需改表，status 是 String）：
`pending → approved → executing → executed | exec_failed`；网关未开时批准仍落 `approved_no_execution`（兼容一期）。

**新增** `services/executor.py`：

```python
def execute_proposal(session: Session, client: FutuClient, record: TradeProposalRecord) -> BrokerOrder:
    """前置断言（任一不满足抛 ExecutionBlocked，中文 message）：
       settings.paper_trading_enabled and settings.futu_enable_trade
       and not settings.trading_halted and record.status == 'approved'
    1) 幂等：broker_orders 已有该 proposal_id 且状态非 failed → 直接返回既有单
    2) 重跑风控：TradeGuardrails.evaluate(原 proposal, 实时组合状态 fetch_account_funds/positions 换算)
       不过 → record.status='exec_failed'，error=风控理由
    3) 价格：富途快照 last；qty=proposal.quantity 按 100 股取整（A股一手）
    4) trade_call('security','place_order', kwargs={code,price(限价滑点带),qty,trd_side,
       order_type=NORMAL, acc_id}, environment='SIMULATE')   # 绝不传 REAL，绝不带 confirmation
    5) 成功 → BrokerOrder(status=submitted, futu_order_id=...)，record.status='executing'
    """
```

- `GET /v1/orders?limit=50`、`GET /v1/orders/{id}`。
前端 08 页"确认执行"按钮接 execute（P2.4 接线，本步 curl 验证即可）。

## P2.3-S4 组合快照与收益归因（09 稿四卡数据源）

**models.py**：

```python
class PortfolioSnapshot(Base):
    __tablename__ = "portfolio_snapshots"
    trade_date: Mapped[date] = mapped_column(Date, primary_key=True)
    total_value: Mapped[float]; cash: Mapped[float]
    positions: Mapped[list[Any]] = mapped_column(JSON, default=list)   # [{symbol,qty,mv,industry}]
    daily_return: Mapped[float | None] = mapped_column(Float)
    benchmark_return: Mapped[float | None] = mapped_column(Float)      # SH.000300 当日
    excess_return: Mapped[float | None] = mapped_column(Float)
    drawdown: Mapped[float | None] = mapped_column(Float)              # 净值相对历史峰值
    source: Mapped[str] = mapped_column(String(16), default="futu-sim")
```

**job** `snapshot_portfolio`（cron 交易日 15:10）：fetch_account_funds + positions → 写当日行；daily_return = total_value/前日 -1；benchmark 从 daily_bars 的 SH.000300 取；drawdown 由净值序列滚动峰值算。持仓行业从 securities.industry_csrc 联出（donut 用）。
**API**：
- `GET /v1/portfolio/overview` → 最新快照 + 行业分布（05 稿 donut：总市值、行业占比）；
- `GET /v1/portfolio/attribution?days=60` → `{dates[], nav[], benchmark_nav[], excess_cum, max_drawdown, benchmark_drawdown}`（09 稿"收益归因/风险控制"两卡 + 净值对比图）。

**验证**：连续两个交易日后 daily_return 与富途 App 模拟账户涨跌一致（±0.1pp）；归因接口序列长度=天数。

## P2.3-S5 信号级归因（09 稿机会/错误复盘）

**models.py**：

```python
class AlertOutcome(Base):
    __tablename__ = "alert_outcomes"
    alert_id: Mapped[int] = mapped_column(Integer, ForeignKey("alerts.id"), primary_key=True)
    horizon_days: Mapped[int] = mapped_column(Integer, default=5)
    realized_return: Mapped[float | None] = mapped_column(Float)
    hit: Mapped[bool | None] = mapped_column(Boolean)
    contribution: Mapped[float | None] = mapped_column(Float)   # suggested_position_change × realized
    evaluated_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), default=utcnow)
```

**job** `evaluate_alerts`（cron 19:40）：对 created_at ≥5 个交易日前且无 outcome 的提醒：realized = 该股 5 交易日收盘收益（daily_bars）；hit 定义：买类(BUY_CANDIDATE/ADD) realized>0；减类(REDUCE/EXIT/STOP) realized<0；WATCH/HOLD/REVIEW 不评（hit=None 不计入命中率）。
**reports.py 改造**：复盘 payload 增加 `signal_attribution: {hit_rate_directional, top_hits: [...], top_misses: [...], by_action: {...}}`；`hit_rate` 环比 = 与前一日报告的差（daily_reports 里翻昨日）。

**验证**：运行若干天后 top_hits/top_misses 非空且 contribution 排序正确；单测用构造数据覆盖买/减两类 hit 判定。

## P2.3-S6 REAL 拦截回归测试 + Kill Switch（安全交付物）

**tests/test_trading_safety.py（新）**，全部离线（FakeFutuModule 复用 test_futu_client.py 的）：
1. `paper_trading_enabled=False` 时 execute_proposal 抛 ExecutionBlocked；
2. `trading_halted=True` 时同样拒绝（即使其他开关全开）；
3. FutuClient：`trade_call(..., environment='REAL')` 在 live_trading_enabled=False 时抛 FutuFeatureDisabledError（已有用例，加一条经 executor 路径不可能传 REAL：静态断言 executor 源码常量 + 运行时 FakeTradeContext 记录 trd_env=='SIMULATE'）；
4. `unlock_trade` 仍被 PERMANENTLY_BLOCKED（既有用例保留）；
5. 幂等：同一 proposal 二次 execute 不产生第二笔 place_order 调用（Fake 计数）。

**API**：`POST /v1/trades/halt` / `POST /v1/trades/resume`（写运行时开关：直接改 get_settings() 不可行——settings 是 lru_cache 只读；实现为 DB 单行表 `runtime_flags(key pk, value bool, updated_at)`，executor 读它；halt 立即生效）。顺带把 `trading_halted` 从 config 移到 runtime_flags（config 键保留作初始值）。

**验证**：`pytest tests/test_trading_safety.py -q` 全绿；halt 后 execute 返回 423（Locked，中文理由）；resume 恢复。
