## 0.2 M3 回填铁律(违反 = 回测结果作废或悄悄偷看未来,逐条对照)

回填最大的风险不是灌不进数据,是**灌进了带未来函数/来源不被审计的数据,让回测虚高**。

1. **available_time 决定一切(未来函数零容忍,承接 M1 铁律#1)。** 回填的每一行都必须带**决策时点
   之前真实可见**的 `available_time`:
   - 财务:`available_time = pubDate + 1 天`(上海零点→UTC),缺 pubDate 才退 `statDate + 45 天`。
     **这套 `financials.py::_availability`(:178-193)已实现,直接复用,不许改口径。**
   - 估值:peTTM/pbMRQ 是**当日盘后可得**,`available_time = trade_date 当日 15:00 上海 → UTC`
     (与日线同口径)。绝不允许把 trade_date T 的估值标成 T 之前可见。
   - 消费端(`engines/factors.py::_load_financial_factors` :343)只取 `available_time ≤ decision_cutoff`
     的最新期——回填口径错了,回测就偷看未来,比灌不进更危险。

2. **来源必须在审计白名单内,否则回测直接忽略(load-bearing)。** 回测的 `_prices_for_date` /
   `_trading_calendar` / `eligible_universe` 全部 `WHERE DailyBar.source IN AUDITED_DAILY_BAR_SOURCES`
   (`provenance.py:3` = `{akshare, baostock, futu, futu-close, sina}`)。
   - 回填 daily_bars 的 `source` 必须 ∈ 这 5 个(BaoStock 走 `"baostock"`)。
   - 板块资金流新增 source(建议 `"futu-daily"`)**必须同步加进** `AUDITED_SECTOR_FLOW_SOURCES`
     (`provenance.py:6`),否则审计层拒绝。
   - 估值新表若有审计集合,同样登记。

3. **复权因子必须与日线同区间同步(承接 M1 铁律#3)。** 回测 engine 用 `DailyBar` **inner join**
   `AdjFactor`(`engine.py:_prices_for_date` :193),**缺复权因子的历史日线会被整行丢弃**。所以 S1
   扩 `daily_bars` 后**必须**用 `sync_adj_factors` 把 `adj_factors` 补到同一起始日,否则多年日线白扩。

4. **幂等 + 断点续传,回填可随时中断重跑。** registry 的 `_job_lock` 只防同名并发,**不防重复回填同
   一区间**。每个回填函数自己保证幂等:先查库已存 → 只补缺 → upsert。照 `sync_financials`
   (按 `(symbol,report_period,metric)` 跳过)/ `sync_daily_bars`(按 per-symbol max trade_date 增量)。

5. **写对库(CWD 坑)。** DB 是相对路径 `sqlite:///data/alphapilot.db`(`config.py:26`),按**进程 CWD**
   解析。回填程序**必须以仓库根为 CWD**、复用 `from alphapilot.db.engine import get_session`
   (共享同一 Settings/引擎),否则会在错目录建空库(根目录那个 0 字节 `alphapilot.db` 就是这么来的)。
   SQLite 写一律走"独立短事务 + `_save_bars_with_lock_retry` 式退避",压短写锁。

6. **覆盖率与缺口如实标注,不得宣称完整。** 回填必然有缺口:停牌/退市/次新股/北交所/数据源缺项。
   每张表回填完,job 的 `stats` 必须报**覆盖率、缺失清单、available_time 口径占比**。幸存者偏差
   (当前 `securities` 不含退市股)**仍然存在,继续显著标注**(承接 M1 铁律#7)。`sector_strength`
   历史补不了,报告里写明 live-only。

7. **回填与重跑解耦,权重不动直到样本外验证。** 严格分两段:先补数据 + 重跑 **M1 单因子 IC**
   (多年窗,看每个因子逐个有没有 alpha)→ 再谈 **M2 重构**(train 窗定权重、test 窗验证)。
   任何"补一点数据 → 看结果不好 → 回头调回填口径/因子定义/权重直到好看"都是 p-hacking(违反
   M2 铁律#2/#6)。**M3 期间绝不开 paper_auto、不动 live/unlock 三闸。**

8. **回测不读 `factor_values` 表(澄清,防走错路)。** M1 回测与 M1 单因子 IC 都走 `backtest/pit.py`
   对每个历史决策日**现场重算**因子(`compute_factors_for_date` + PIT 过滤),**不读 `factor_values`
   缓存表**。所以 M3 关键路径**回填的是输入底表**(daily_bars/adj_factors/financial_indicators/估值/
   sector_flow),**不是 factor_values**。回填 factor_values 只为 live 展示(S8,次要、可选)。

## P3.3-S1 daily_bars + adj_factors 向前扩展到多年 ✅ done 2026-07-24

**目标**：把回测可用区间从当前 ~2024-03 起扩到**多年起点**,给足统计效力。目标起始日设 `2019-01-01`
(约 7.5 年、~1800 交易日,远超 M2 的 301 日);若 Tushare 复权因子额度扛不住,允许收窄到 `2021-01-01`

**做法**:
1. **daily_bars 扩历史**：`jobs/daily_bars.py::sync_daily_bars` 当前冷启动只回溯 `lookback_days=450`
   (`:237`)。给它加一个可选 `start_date: date | None = None`(或直接调大 `lookback_days`),使
   `start = start_date`(冷启动)覆盖到 2019-01;全市场跑。写入 `source="baostock"`(北交所走 Sina)。
   复用 `_save_bars_with_lock_retry`(:119)短事务退避、连续 20 失败熔断。
2. **adj_factors 同区间补齐(铁律#3,必须)**：`jobs/backtest_jobs.py::sync_adj_factors_job`(:55)
   → `backtest/adjust.py::sync_adj_factors`(:373),Tushare `adj_factor` 接口(低积分账号该接口**有权限**,
   凭据 `.env` 的 `ALPHAPILOT_TUSHARE_TOKEN`)。扩到与 daily_bars 相同起始日。**这是 S1 最重的一步**
   (5200 股 × 7 年,Tushare 限频),**先跑、留足时间**;跑完前不要进 S7。

**验证**(架构师会独立抽查):

  (否则该股历史日线会被 inner join 丢弃)。

## P3.3-S4 因子引擎估值改造:pe/pb_percentile 读历史表
