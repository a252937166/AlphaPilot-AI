# P3.3 日常预测链补偿 hotfix（2026-07-30）

## 事故结论

- 盘后 `sync_daily_bars`、`sync_adj_factors`、`sync_valuation_daily` 的真实运行时间
  已经超过原定的 19:30 因子计算点。
- 原 `compute_factors` 只拦截日线与复权任务的 `running` 状态，没有拦截估值同步，
  因而存在读取当日半截估值截面的风险。
- 19:30 失败或 19:40 风格任务跳过后，没有依赖就绪后的自动补偿；API 重启错过
  单点 cron 后也不会追赶。

## 修复

1. live 因子计算增加日线、复权、估值三路精确终态合同：
   - producer JobRun 必须为目标日期终态；
   - 复权与估值的 CN-listed 当日覆盖率必须至少 99%；
   - 估值必须 `is_complete=true`、`symbols_failed=0`、`failures=[]`；
   - `available_time` 仍受 19:30 Asia/Shanghai PIT 截止约束。
2. 新增 `reconcile_prediction_outputs`：
   - 盘后及次日补偿窗口每 15 分钟检查一次；
   - 仅按 `compute_factors → compute_style_daily` 顺序补算；
   - 输出完整且晚于上游终态时 no-op；
   - 支持 API 重启后追赶最近一个完整交易日。
3. 新增 `adj_factors(trade_date, symbol)` 索引；因子完整性按
   `ix_factor_date(factor, trade_date)` 分组检查，避免多年表全表扫描。
4. 显式历史因子调用保留原语义；本 hotfix 不读取研究 test 窗，不修改权重。

## 安全边界

- 未调用提醒刷新、提案、订单或交易路径。
- `research`、`live=false`、`paper_auto=false` 与 `unlock_trade` 屏蔽保持不变。
- S2/S7/S9 的完成状态与验收门未改变。
