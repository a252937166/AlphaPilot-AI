## 1. 只读最终验收检查器

入口：

```bash
.venv/bin/python scripts/run_p3_m3_s2_acceptance.py \
  --db data/alphapilot.db \
  --as-of-date 2026-08-01 \
  --shard-db aliyun=data/phase3-s2/financial-s2-latest.db \
  --shard-db dogcloud=data/phase3-s2-dog/financial-s2-latest.db \
  --shard-db us38=data/phase3-s2-us38/financial-s2-latest.db \
  --shard-db ussea=data/phase3-s2-ussea/financial-s2-latest.db
```

检查器对所有 SQLite 输入使用 `mode=ro` 与 `PRAGMA query_only=ON`，不导入 BaoStock provider，
不打开网络，不写数据库。`--as-of-date` 必须显式给出，用来冻结 40 个已完成季度，避免在季度
边界重跑时悄悄改变验收窗口。

输出包括：

- BaoStock 支持证券分母，以及总覆盖和五个 metric 的逐项 rows/symbols/non-null；
- `provider_pub_date_end_of_day` 占比、fallback 数和 available_time 异常；
- `(symbol, report_period, metric)` 重复键；
- 40 季度正断点（完整五指标 bundle）与
  `Security.profile.financial_no_data_periods` 负断点的闭环；
- partial、unresolved、正负重叠、非法/重复负断点；
- 四份远端最终快照内最新 `sync_financials` JobRun 的完整幂等空跑合同；
- 确定性五股 pubDate 计划。

本地可检查项通过只表示可以进入获准的五股真实 pubDate 对拍。`ready_for_s2_signoff` 固定保持
false，直到外部对拍证据经架构师复核签字。

## 2. 幂等空跑判据

阿里云、狗云、US38、US-SEA 各自在自己的最终 staging DB 上完成一次空跑，再各自导出静态
快照。检查器不采信本机旧 `job_runs` 代替远端证据。

最新 JobRun 必须同时满足：

- `status=ok`、`error=null`、`finished_at` 非空；
- `quarters_requested=40`，边界与该分片合同完全一致；
- `symbols_processed=symbols_total`；
- `symbols_skipped + symbols_unsupported = symbols_total`；
- `symbols_done=0`、`symbols_with_data=0`、`symbols_failed=0`、`failures=[]`；
- `financial_quarters_queried=0`、`prior_revenue_queries=0`；
- `metrics_inserted=0`、`metrics_updated=0`；
- `unavailable_checkpoints_added=0`；
- `provider_probe_requests=1`、`provider_requests_estimated=1`；
- `stopped_for_request_budget=false`、`resume_symbol=null`、`is_complete=true`。

仅有 `JobRun.status=ok` 不足以通过：额度分片正常停机也会是 `ok`，但其
`is_complete=false`。

## 3. pubDate 五股计划（本批只生成，不执行）

检查器从合并库中取每只支持证券在目标 40 季度内最新的、具有
`provider_pub_date_end_of_day` 的 ROE 行，再按
`sha256(seed|symbol|report_period)` 固定排序取前五。这个方法不看对拍结果、不失败后换样本，
避免 cherry-pick。

计划输出每股：

- symbol、report_period、year、quarter；
- 本地 payload 的 pubDate、available_time、source_field；
- 计划调用的 `BaoStock query_profit_data`。

待 S2 采集完成且出口额度获准后，才允许另行执行真实对拍。执行铁律：

1. 单进程、单连接、最多五次真实 query；
2. `10001011` 或任一 query 失败立即停止，不重试、不换样本；
3. 对拍 `statDate`、`pubDate`，并复算
   `pubDate + 1 天上海零点 → UTC available_time`；
4. 必须 5/5 一致；缺行、失败或不一致都不得签认。

获准执行时，先把只读预检的完整 JSON 原样复制到获准出口，再运行：

```bash
PYTHONPATH=src .venv/bin/python scripts/run_p3_m3_s2_pubdate_audit.py \
  --plan p3.3-s2-final-preflight.json \
  > p3.3-s2-pubdate-evidence.json
```

执行器不打开生产数据库，先验证固定计划恰好五只且逐项完整，再单次 login、按原顺序执行最多
五次 `query_profit_data`，不重试、不换样本；任一 provider 错误立即停止，所有路径均 logout。
stdout 只输出机器可审计 JSON，进程退出码 `0` 表示 5/5 对拍且 logout 成功，`2` 表示证据不
通过，`1` 表示计划文件或客户端模块无法加载。测试可注入 fake client，离线验证完整路径。
