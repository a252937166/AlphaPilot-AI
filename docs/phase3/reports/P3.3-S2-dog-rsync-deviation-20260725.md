# P3.3-S2 Dog Cloud 回传传输偏差记录（2026-07-25）

> ⚠ DEVIATION: Dog Cloud 的快照回传由压缩 SCP 改为显式、可审计的 rsync 断点续传；仅 Dog
> LaunchAgent 使用该模式，阿里云、LAX 与 CLI 默认仍使用压缩 legacy SCP。

## 触发证据

- 默认 SFTP SCP 在 `100,892,672 / 104,796,160` 字节处停滞数分钟。
- 强制 legacy SCP（`scp -O`）再次尝试时，在约 45 MiB 处 `lost connection`。
- 两次失败都没有替换正式 `financial-s2-latest.db`；失败临时文件已安全清理。

## 处置契约

- CLI 新增 `--transfer-mode {scp,rsync}`，默认 `scp`。
- Dog LaunchAgent 固定传 `--transfer-mode rsync`，并显式指定经能力检查、支持
  `--append-verify` 的 GNU rsync 二进制。
- rsync 使用 SSH BatchMode、显式端口、连接超时与 keepalive，参数固定为
  `-z --partial --append-verify`。
- 下载写入固定 `.financial-s2-latest.db.rsync-partial`；失败最多三次小退避重试，最终失败保留
  `0600` partial 供下次续传。
- 只有 rsync 成功且本地 SHA-256 与远端 manifest 一致后，才以 `0600` 原子替换正式快照；
  SHA 不一致时保留 partial，绝不覆盖已接受快照。
- 生产库 `trade_proposals / broker_orders = 1 / 1` 前置门、只补缺导入和 post-check 均保持不变。

## 投产实证

macOS 自带 `/usr/bin/rsync` 是 OpenRsync 兼容版，不支持 `--append-verify`，不能用于此模式。
安装器默认要求 `/usr/local/bin/rsync`，也可通过 `ALPHAPILOT_DOG_RSYNC_BIN` 指向另一条绝对路径；
不支持该能力时安装器和运行时都会明确失败。

2026-07-25 实际安装并验证本机 GNU rsync `3.4.4`；狗云远端为 GNU rsync `3.1.2`，两端均支持
`--append-verify`。重装 `com.alphapilot.s2-financial-pull-dog` 后，RunAtLoad 首轮真实回传：

- LaunchAgent `last exit code=0`；
- `transfer_mode=rsync`、`transfer_attempts=1`，无残留 partial；
- 远端与本地快照 SHA-256 同为
  `8f17c340b0a55379f960c261aaf0b38d0a8765b13ce2fe1d03dc6d8f4fb34cfc`；
- 远端快照 `220,610` 行 / `1,257` 股；
- 本地幂等合并 `inserted=0`、`already_present=220,610`，仍为
  `268,750` 行 / `1,504` 股；
- `trade_proposals / broker_orders` 写前写后均严格为 `1 / 1`。

该验证只执行远端 SQLite online backup、SSH 文件传输与本地幂等合并，没有建立 BaoStock
连接，也没有触碰交易三闸。
